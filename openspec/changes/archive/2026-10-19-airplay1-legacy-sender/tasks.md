## 4. Media server with range support

- [x] 4.1 Implement the media server on `async-http` with an explicit router replacing the Cuba app in `lib/airplay/server/app.rb`, and drop `reel`, `reel-rack`, `cuba` and `rack` from `airplay.gemspec` and the `Gemfile`. Verify: `rg -n 'reel|cuba|rack' lib airplay.gemspec Gemfile` reports nothing, and `rake test:protocol` fetches a published fixture and receives its bytes.
- [x] 4.2 Implement the publish contract: an opaque per-session identifier, a stable mapping per file, distinct identifiers per file, no filesystem path or file name in the URL, and an absolute URL carrying the advertised host and the actual bound port (configured port when set, otherwise the port read back from the socket after binding rather than the former open-and-close probe). Verify: `rake test:protocol` — the stability, distinctness, path-traversal and configured-port scenarios; `rake test:unit` — a published path shares no component with the file's path.
- [x] 4.3 Implement the lifecycle: start the listener on the first publish with the returned URL servable immediately (no readiness polling), stop and unbind on session close, and bind nothing for sessions that only play remote URLs or push pictures. Verify: `rake test:protocol` — the URL serves a file right after publish, rebinding the released port after close succeeds, and a remote-only session records no bound port.
- [x] 4.4 Implement the response contract: `200` with `Content-Length`, `Accept-Ranges: bytes` and a derived `Content-Type` for a whole-file request; `206` with `Content-Range` for closed, open-ended and suffix ranges; `416` with `Content-Range: bytes */<size>` for unsatisfiable ranges and for any range on a zero-byte file; `HEAD` with and without a range returning the same headers and no body; `404` with no file bytes for identifiers that were never published or whose session ended. Verify: `rake test:protocol` — the range-client helper asserts each status, header and body slice against the three fixtures.
- [x] 4.5 Serve bodies from the file with an explicit offset and length, so a range request reads only the requested bytes and never copies the file into memory. Verify: `rake test:protocol` — an instrumented handle reports no more than the requested byte count for a range request against a fixture larger than the test lane's memory budget.
- [x] 4.6 Serve concurrently with the control plane on one reactor: a transfer in progress does not delay a control command and vice versa, and one connection cannot head-of-line block the other. Verify: `rake test:protocol` — a slow range transfer is interleaved with `/playback-info`, and both complete with correct results while the transfer is still in flight.
- [x] 4.7 Back the content-type resolution with the media type table shared with the media compatibility inspection, falling back to `application/octet-stream` for unknown or missing extensions, and keep compatibility an inspection that never gates playback. Verify: `rake test:unit` for the type table and `.mov`/unknown-extension cases; `rake test:protocol` serving both files with the expected `Content-Type`.
