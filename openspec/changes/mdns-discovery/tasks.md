## 1. mDNS message codec

- [ ] 1.1 Add the mDNS message codec on top of the stdlib DNS message codec in the runtime
      dependency set: build a query for a service type and decode a datagram into name, TTL and
      resource triples for PTR, SRV, TXT, A and AAAA, keeping uninterpreted record types' raw data;
      verify with unit tests over hand-authored packet fixtures (one per record type plus one
      unknown type) committed under `test/fixtures/mdns/`, never generated by our own encoder
- [ ] 1.2 Decode TXT payloads into an ordered key/value map: split on the first `=`, keep empty
      values, keep duplicate keys' last value, keep bytes that are not valid UTF-8; verify unit tests
      assert each case against hand-authored TXT payloads
- [ ] 1.3 Add TXT payload encoding for the harness responder and verify the encoder's output decodes
      back to the same map and matches a hand-authored byte expectation
- [ ] 1.4 Reject malformed input explicitly: resolve label-compression pointers, and refuse to
      produce a partial parse when a datagram is truncated (TC bit set) or a length runs past the
      end; verify unit tests assert the protocol error type from the runtime taxonomy for each case
- [ ] 1.5 Add a mutation test over a fixed list of committed seeds that flips bytes in the packet
      fixtures; verify decoding either succeeds or raises the documented protocol error, never an
      unexpected exception and never a hang

## 2. mDNS responder double (test harness)

Depends on `runtime-async-reset`'s dev-only fake-device package and harness multicast responder
skeleton; this group adds the DNS-specific behaviour. Its requirements are the `Discovery `-prefixed
ADDED requirements in `specs/test-harness/spec.md` (the `test-harness` capability is owned by that
sibling change).

- [ ] 2.1 Implement the responder double in the fake-device package: advertise one or more service
      instances on an interface usable in tests with configurable instance name, service type, SRV
      target, port, TTL and address family, answering PTR, SRV, TXT, A and AAAA; verify a protocol
      test discovers a configured instance through a real socket round-trip with avahi absent and
      assert its name, host and port
- [ ] 2.2 Add the fault knobs — withhold or delay an instance's SRV answer, answer a later query for
      the same instance with a conflicting TXT map, answer only on the IPv6 multicast group, and drop
      a configured fraction of answers; verify one protocol test per knob asserts the browser's
      documented behaviour (withheld SRV: no record; conflicting TXT: the newer map once its TTL
      applies; IPv6-only: an IPv6 address in the record; loss: the browse returns in its window with
      retry queries logged)
- [ ] 2.3 Record received traffic behind an accessor: source address, arrival order and decoded
      message; verify a test browsing with the responder asserts every recorded packet is a query,
      and a second test sends a query to the library socket and asserts no response is recorded (the
      sender never advertises)
- [ ] 2.4 Support unadvertising an instance with a TTL-0 record; verify a protocol test asserts the
      instance disappears from enumeration after the goodbye and reappears after re-advertisement
- [ ] 2.5 Verify the double is absent from both runtime gemspecs' file lists and that a protocol-lane
      run with no avahi installed and no external network passes

## 3. Browser, resolver and cache

- [ ] 3.1 Implement the browse and resolve state machine: query both service types on every selected
      interface, correlate PTR, SRV, TXT and A/AAAA answers by instance name, and report a record
      once SRV and at least one address are known; verify protocol tests against the responder double
      cover `_airplay._tcp`, `_raop._tcp` and the `<identifier>@<name>` RAOP instance-name shape
- [ ] 3.2 Implement the structured record (instance name, service type, SRV target, addresses with
      their interface, port, TXT map, TTL, capabilities) and take the port from SRV only; verify a
      protocol test with SRV port 5000 asserts the record's port and that no accessor returns a
      concatenated address-and-port string
- [ ] 3.3 Implement the TTL-aware cache keyed by service instance with per-record expiry, re-resolve
      on expiry and removal on a TTL-0 goodbye; verify tests driven by the harness clock assert reuse
      inside the TTL (the responder logs no second query), a re-query after expiry and goodbye
      removal, all without wall-clock sleeps
- [ ] 3.4 Implement interface selection (membership and binding per interface and family) and the
      deterministic address preference (receiving interface first, IPv4 before IPv6, link-local last,
      link-local reported with its scope); verify tests for the IPv6-only responder, for one instance
      answering on two interfaces collapsing into one record with both addresses, and for a
      link-local answer keeping its scope identifier
- [ ] 3.5 Implement the advertised-address override from configuration, applied to the address the
      library hands to receivers while sockets keep their local bind address; verify a test asserts
      the record's advertised address differs from the socket's local address when the override is
      set
- [ ] 3.6 Implement the bounded browse result: a caller-set window, cancellation, the reason the
      browse ended, and an empty network returning an empty result rather than raising; and make an
      unusable interface raise the runtime taxonomy's transport error with its documented code;
      verify tests assert no exception on an empty network, the cancelled reason on cancellation, and
      the typed error and code for a non-existent interface name
- [ ] 3.7 Implement `Airplay.devices` as an enumerable of records with lookup by display name and by
      address or identifier, deduplicated by service instance, browsing only when the cache is empty
      and autodiscovery is enabled; verify tests reproduce the CLI's assumptions (`Airplay["Apple TV"]`,
      `Airplay.devices.first`), assert a second browse in the same process sends no query while the
      cache is warm, and assert a second browse does not duplicate an instance
- [ ] 3.8 Verify reactor safety: two concurrent browses in one reactor make progress while a
      responder delays its answers, and a browse cancelled mid-flight leaves no socket or task behind
      (assert the responder no longer receives queries and the test process has no lingering sockets)

## 4. TXT normalisation and capability model

- [ ] 4.1 Implement the 64-bit mask decoder (`0xLOW,0xHIGH` as `(HIGH<<32)|LOW`, single word
      accepted, `ft` fallback, missing or malformed reported unknown); verify unit tests with
      `0x40000a00,0x80300`, `0x5A7FDFD5,0x3C155FDE`, a `ft`-only record and `features=zz`
- [ ] 4.2 Implement the status flags (`sf` preferred over `flags`) and the password, PIN and
      legacy-pairing predicates including the `pw=true` case; verify unit tests per bit and per
      `pw` value
- [ ] 4.3 Implement version values with segment-wise comparison and the buffered-audio and PTP
      gates, with a gate whose version input is unknown reporting unavailable; verify unit tests at,
      below and above each gate value plus the unparsable-version case
- [ ] 4.4 Implement identity, group and access-control normalisation: `deviceid`, `pi` with `psi`
      fallback, `pk`, `gid`/`pgid`/`tsid`/`gpn`, the leader flags as booleans, the compound group
      identifier reduced to its leading value, and `acl`/`act`/`rsf` with the restricted predicate;
      verify unit tests with a TXT fixture carrying every documented key plus an unreadable group
      identifier and an unrecognised `acl` value
- [ ] 4.5 Implement the named capability predicates (media, control, pairing, AirPlay 2,
      transient pairing) over the mask and verify a table-driven unit test asserting each predicate
      against the reference device feature values from the design and against an all-zero mask
- [ ] 4.6 Keep every TXT key and value verbatim in the raw map, including RAOP hints and unknown
      keys; verify a unit test with `cn=0,1`, `et=0,3,5` and an unknown key reads all three back
      unchanged
- [ ] 4.7 Implement capability refresh with source-tagged fields: a later authoritative source
      replaces the values it defines without merging, TXT-only values stay readable as diagnostics;
      verify a unit test reconciles a TXT-only fixture with a later `/info`-shaped fixture and
      asserts the wire values win, the source of each normalised field is reported, and the original
      TXT map is unchanged
- [ ] 4.8 Wire the capability model into discovery records and verify a protocol test asserts the
      capabilities of an instance advertised by the responder double match its configured TXT map
