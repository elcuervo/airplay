# test-harness Specification

## Purpose
An in-process virtual AirPlay receiver lets every protocol part of this plan be validated
deterministically, without physical hardware or external services, and bidirectionally — the
sender is tested against an independent implementation of the same wire contract.

## Requirements

### Requirement: In-process virtual receiver

The harness SHALL provide a virtual AirPlay receiver that starts inside the test process without
system services, is reachable at an address the test knows, and serves the control endpoints of the
mode it was started in. The multicast responder that makes it discoverable is owned by the
discovery capability, not by this one.

```ruby
Airplay.sync do
  receiver = Airplay::FakeDevice::Receiver.new(
    record: { name: "Studio", model: "AppleTV6,2", features: 7 }
  ).start

  body = Airplay::Session.open(receiver.device) { |session| session.get("/record").body }
  JSON.parse(body) # => {"name"=>"Studio", "model"=>"AppleTV6,2", "features"=>7, "password"=>false}

  receiver.stop
end
```

#### Scenario: Receiver runs with no system services

- **WHEN** a protocol test starts the virtual receiver on a loopback interface
- **THEN** a client connects to it at that address and completes the mode's handshake without
  physical hardware or any background daemon

#### Scenario: Configured record is exposed

- **WHEN** a test configures the receiver's service record, model and capability mask
- **THEN** the receiver exposes that record, and where the discovery capability is present a client
  browsing for it observes exactly those capabilities

### Requirement: Per-mode protocol coverage

The virtual receiver SHALL be extensible with protocol modes — legacy control, pairing and encrypted
control, video play queue, and an audio sink — and SHALL record the traffic it received so tests can
assert on wire content, ordering and timing.

```ruby
receiver.exchanges.last
# => #<struct Airplay::FakeDevice::Receiver::Exchange
#      method="POST", path="/command",
#      headers={"content-type"=>"application/x-apple-binary-plist", "x-test"=>"yes"},
#      body="payload">
```

#### Scenario: Wire assertions

- **WHEN** a test drives a mode and then asks the receiver for the recorded exchanges
- **THEN** the recorded requests expose method, path, headers and decoded body for assertion

#### Scenario: Independent implementation

- **WHEN** a mode's behaviour is asserted
- **THEN** both the client and the receiver must agree on the wire format, and a mismatch fails the test rather than being normalized away

### Requirement: Fault injection

The virtual receiver SHALL support per-test fault configuration covering delayed or absent
responses, dropped or truncated payloads, connection resets, error status codes, authentication
challenges, and corrupted payload bytes. Corrupted authentication tags are added by the pairing
mode that first parses them.

```ruby
receiver = Airplay::FakeDevice::Receiver.new(
  faults: { 1 => { kind: :delay, seconds: 1 } }
).start

Airplay::Session.open(receiver.device, timeout: 0.1) { |session| session.get("/record") }
# raises Airplay::TimeoutError with code :timeout
```

```ruby
Airplay::FakeDevice::Receiver.new(faults: { connection: :reset }).start
# the next request raises Airplay::TransportError with code :connection_lost
```

#### Scenario: Fault is selected per test

- **WHEN** a test configures a delayed response for one request
- **THEN** the client's timeout path is exercised and no other request of that test is affected

#### Scenario: Failure paths are observable

- **WHEN** the receiver is configured to reject authentication
- **THEN** the client raises its documented authentication error rather than retrying indefinitely

### Requirement: Deterministic time

Tests that depend on timing SHALL use an injectable or advanceable clock, so pacing, anchoring and
multi-room tolerance can be asserted without sleeping on the wall clock.

```ruby
clock = Airplay::FakeDevice::FakeClock.new
clock.advance(60)
clock.now # => 60.0
```

#### Scenario: Pacing asserted without wall-clock waits

- **WHEN** a timing test advances the injected clock past a scheduled instant
- **THEN** the sender's behaviour at that instant is observable immediately, with no real-time sleep

### Requirement: Vectors sourced from outside the implementation

Golden wire vectors SHALL be derived from external references or from committed captures, and SHALL
NOT be generated by the implementation under test.

```ruby
# test/fixtures/pairing/hkdf_control_read.bin is captured from the reference implementation
vector = File.binread("test/fixtures/pairing/hkdf_control_read.bin")
assert_equal vector, derive_control_read_key(seed)
```

#### Scenario: A regression cannot redefine the expectation

- **WHEN** a wire-format test runs
- **THEN** it compares against a fixture authored independently of the code path it validates

### Requirement: Opt-in hardware validation

A hardware lane SHALL exist for validating against real receivers, gated by environment
configuration, skipped when that configuration is absent, and recording the device model,
firmware version and outcome of each run.

```sh
AIRPLAY_HARDWARE_HOST=192.168.1.12 \
AIRPLAY_HARDWARE_PORT=7000 \
nix develop -c bundle exec rake test:hardware
```

#### Scenario: Hardware absent

- **WHEN** the hardware lane runs with no receiver configured
- **THEN** its tests skip with a reported reason and the exit status is successful

#### Scenario: Hardware present

- **WHEN** a receiver is configured and the hardware lane runs
- **THEN** the observed device identifiers and outcomes are recorded in the lane output

### Requirement: Discovery in-process mDNS responder double

The test harness SHALL provide an mDNS responder double that advertises configurable service
instances — instance name, service type, SRV target, port, TTL and address family — over the
multicast destinations on an interface usable in tests, without external services, and records
every query it receives with its source and decoded contents.

```ruby
Airplay.sync do
  responder = Airplay::FakeDevice::MDNSResponder.new(
    port: 55_353, interfaces: ["lo0"]
  ).start

  responder.advertise(
    name: "Living Room",
    type: "_airplay._tcp.local.",
    target: "living-room.local.",
    port: 7000,
    txt: { "deviceid" => "AA:BB:CC:DD:EE:FF", "features" => "0x5A7FDFD5,0x3C155FDE" }
  )

  result = Airplay::Discovery::Browser.new(
    port: 55_353, interfaces: ["lo0"]
  ).browse(window: 0.5)

  result.records.first.port # => 7000
  responder.stop
end
```

#### Scenario: Discoverable without system services

- **WHEN** a test starts the responder double with one configured instance and browses
- **THEN** the instance is discovered with no system daemon installed and no external network used

#### Scenario: Received traffic is inspectable

- **WHEN** a test asks the responder double for the traffic it recorded
- **THEN** each entry exposes the source address, the arrival order and the decoded query or answer

### Requirement: Discovery harness fault injection

The responder double SHALL support per-test discovery faults: withholding or delaying an instance's
SRV answer, answering with a TXT record that conflicts with an earlier answer for the same instance,
answering only on IPv6, and dropping a configured fraction of answers.

```ruby
responder.advertise(
  name: "Silent",
  type: "_airplay._tcp.local.",
  target: "silent.local.",
  port: 7000,
  fault: :withhold_srv
)

responder.advertise(
  name: "Lossy",
  type: "_airplay._tcp.local.",
  target: "lossy.local.",
  port: 7000,
  drop: 0.5
)
```

#### Scenario: Withheld SRV answer

- **WHEN** the responder withholds SRV answers for an instance it announced
- **THEN** the browse result contains no record for that instance

#### Scenario: Conflicting TXT answer

- **WHEN** the responder answers the second query for an instance with a different TXT map
- **THEN** the record reflects the newer map once its TTL has replaced the earlier one

#### Scenario: IPv6-only answer

- **WHEN** the responder is configured to answer only on the IPv6 multicast group
- **THEN** the instance is discovered with an IPv6 address

#### Scenario: Dropped answers

- **WHEN** the responder drops a configured fraction of its answers
- **THEN** the browse still returns within its window and the responder's log shows the retry queries
